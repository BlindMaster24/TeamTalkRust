# Migration Guide: 2.x -> 3.0 (Bot Framework)

This guide covers migration to the new high-level bot framework APIs added for
the 3.0 line.

## What changed

- Added bot runtime APIs:
  - `Bot`, `BotBuilder`, `BotConfig`
  - `AsyncBot`, `AsyncBotBuilder`, `AsyncBotConfig` (`bot` + `async`)
- Added routing and command APIs:
  - `Router::on_command`, `Router::command_group`, `Router::on_unknown_command`
- Added middleware and scheduler:
  - `Middleware`, `CommandOnly`, `RateLimitBySource`
  - `Scheduler`, `JobErrorPolicy`
- Added state and dialog abstractions:
  - `StateStore`, `MemoryStateStore`
  - `RedisStateStore` (`bot-redis`)
  - `SqliteStateStore` (`bot-sqlite`)
  - `DialogMachine`, `DialogState`, `Context::dialog_*`

## Upgrade steps

1. Enable bot features in `Cargo.toml`.
2. Move manual `poll` loops into `Bot::run()` / `AsyncBot::run()`.
3. Move command parsing into `Router::on_command`.
4. Move custom per-user state maps into `StateStore` usage.
5. For multi-step conversations, use `DialogMachine` via `Context::dialog_*`.

## Cargo feature migration

```toml
[dependencies]
teamtalk = { version = "3.0.0", features = ["bot"] }
```

Optional production storage:

```toml
[dependencies]
teamtalk = { version = "3.0.0", features = ["bot", "bot-redis"] }
# or
teamtalk = { version = "3.0.0", features = ["bot", "bot-sqlite"] }
```

Async runtime:

```toml
[dependencies]
teamtalk = { version = "3.0.0", features = ["bot", "async"] }
```

## Before / after

Before (manual loop):

```rust
loop {
    if let Some((event, msg)) = client.poll(100) {
        // parse command, route, state, retries...
    }
}
```

After (bot runtime):

```rust
let router = Router::new()
    .on_command("start", |ctx| {
        ctx.dialog_start("onboarding", "ask_name");
        Ok(HandlerResult::Continue)
    })
    .on_unknown_command(|ctx| {
        if let Some(text) = ctx.message.text() {
            let _ = text.send_private(ctx.client, "Unknown command");
        }
        Ok(HandlerResult::Continue)
    });

let mut bot = Bot::builder(client).with_router(router).build();
bot.run()?;
```

## Behavior and stability notes

- `AsyncClient` remains `Send` and intentionally not `Sync`.
- Bot handlers and middleware are panic-guarded in router dispatch; panic is
  surfaced as an error instead of aborting the process.
- Storage adapters are optional and feature-gated to keep default builds light.
